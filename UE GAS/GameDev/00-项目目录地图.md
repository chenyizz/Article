# 项目目录地图

> 这是**全局总纲**：告诉你"每一段代码到底写在哪个文件夹、哪个文件里"。
> 读任何知识单元前先看这里；每个单元第 4 节「物理落位」都必须和本文件保持一致。
> 本文件是**活文档**：项目里新增/移动文件/文件夹时，同步更新本文件。

## 0. 先搞懂三个词

- **物理位置**：文件在硬盘上的真实路径，例如 `Source/GameDev/Combat/MyFireAbility.cpp`。这是你要打开、新建文件的地方。
- **逻辑框架**：脑子里给系统分的层，例如"基础设施层/战斗内核层/系统层"。它不占硬盘位置，只帮你理解谁依赖谁。
- **落位**：把一个逻辑概念（比如"资产管理器"）放到一个物理位置（比如 `Source/GameDev/Framework/`）。本文件专门解决"落位"。

**一句话**：逻辑框架告诉你"这东西属于谁"，物理位置告诉你"这东西住哪"。两者在本文件里一一对应。

> **别混淆两个"模块"**：
> - **内容模块目录**（本笔记仓库）`UE GAS/GameDev/NN-模块名/`（如 `02-引擎基础/`）——**笔记**的组织方式。
> - **物理模块（DLL）**（UE 工程）`Source/<模块名>/`（如 `GameDev`、`GameDevCore`）——**代码**的编译单元。
> 本文件主要讲代码的物理模块；笔记内容目录见 `00-导航.md`。
>
> **三维落位**：每段代码/每个类都必须同时说清 `物理模块(DLL)` + `逻辑层` + `具体文件`，详见第 1.5 节与模板第 4 节。

## 1. UE 项目根目录长什么样

假设项目放在 `D:\UEProjects\GameDev\`（路径随意，以下用相对路径表示）：

```
D:\UEProjects\GameDev\                 ← UE 项目根目录
│
├── GameDev.uproject                   ← 项目描述文件（双击它打开工程；记录模块和插件清单）
│
├── Config\                            ← 所有配置（纯文本 ini）
│   ├── DefaultEngine.ini              ← 引擎/渲染/默认地图/AssetManager 等
│   ├── DefaultGame.ini                ← 项目信息、打包规则
│   └── DefaultInput.ini               ← 旧输入（我们主要用 Enhanced Input，放 Content）
│
├── Content\                           ← ★ 非代码资产：蓝图、地图、DataAsset、材质、UI
│   ├── Maps\                          ← 关卡（.umap）
│   │   └── L_Prototype.umap
│   ├── Blueprints\                    ← 蓝图（.uasset）
│   │   ├── B_PlayerCharacter.uasset
│   │   └── ...
│   ├── Data\                          ← DataAsset / DataTable / CurveTable
│   │   ├── DA_...
│   │   └── DT_...
│   ├── UI\                            ← CommonUI 的 Widget 蓝图
│   ├── Characters\                    ← 角色骨骼/网格/动画
│   └── Effects\                       ← 特效/材质
│
├── Source\                            ← ★ C++ 代码区（引擎只认这里的代码）
│   ├── GameDev.Target.cs              ← 游戏运行目标的编译配置（列出要编的模块）
│   ├── GameDevEditor.Target.cs        ← 编辑器目标的编译配置
│   ├── GameDevCore\                   ← ★★ 物理模块 #1（DLL）：契约与共享地基
│   │   ├── GameDevCore.Build.cs       ← 模块依赖清单（K03 建）
│   │   ├── GameDevCore.h / .cpp       ← 模块入口（K03 建）
│   │   └── ...（Interfaces/Tags/Types 等子目录由后续单元按需创建，禁止预建空目录）
│   └── GameDev\                       ← ★★ 物理模块 #2（DLL）：玩法实现
│       ├── GameDev.Build.cs           ← 模块依赖清单（K03 讲）
│       ├── GameDev.h / GameDev.cpp    ← 模块入口（K01/K03 讲）
│       ├── Framework\                 ← 基础设施层
│       ├── Input\                     ← 输入层（数据驱动输入配置）
│       ├── Character\                 ← 角色、PlayerState、AttributeSet
│       ├── Combat\                    ← GAS 技能、Effect、Cue
│       ├── Equipment\                 ← 装备、词条、掉落
│       ├── NPC\                       ← NPC、好感度、对话
│       ├── UI\                        ← UI 的 C++ 基类（Widget 逻辑）
│       └── ...（按系统继续加，见第 3 节）
│
├── Plugins\                           ← 项目自带插件（后期 GAS 扩展/自研模块放这里）
│
├── Binaries\                          ← 编译产物（.dll/.exe），git 忽略
├── Intermediate\                      ← 编译中间文件，git 忽略
├── Saved\                             ← 日志、自动保存、截图，git 忽略
└── .gitignore                         ← 把上面三个忽略掉
```

### 记忆口诀
- `Content/` = **给编辑器看的东西**（蓝图、数据、美术），不进 C++ 编译。
- `Source/` = **给编译器看的东西**（C++），这里改完要重新编译。
- `Config/` = **开关按钮**（ini 配置），改类名、默认地图、插件开关都在这。
- `Binaries/Intermediate/Saved` = **垃圾场**，随便生成，不要提交 git。

## 1.5 物理模块规划（DLL 层）

> 一个"物理模块" = 一个能编译成 DLL 的代码集合 = 一个 `Source/<模块名>/` 目录。
> 模块在写代码前就规划好**终身职责**，后续单元往里填，**不建"练习用"模块**。

| 物理模块(DLL) | 类型 | 终身职责（真正用途） | 依赖方向 | 引入 |
|---|---|---|---|---|
| `GameDevCore` | Runtime | **契约与共享地基**：通用接口（`IInteractable`）、Native GameplayTags、共享枚举/结构（伤害类型、属性 ID）、消息结构体、通用工具。**禁止放玩法实现逻辑**（如 Combat 计算 → 属 `GameDev`） | 只依赖引擎模块（Core/CoreUObject/Engine/GameplayTags） | K03 建骨架 |
| `GameDev` | Runtime | **玩法实现**：Framework、Character/ASC、Combat、Equipment、NPC、World、UI | `GameDevCore` + GAS/CommonUI 等 | K01 已建 |
| `GameDevEditor` | Editor | **编辑器扩展**：数据校验、自定义 Details、资产工厂、蓝图节点 | `GameDev` + `GameDevCore` + UnrealEd | 需要时（约 K12/K26） |

**依赖方向（箭头 = 依赖）**：`GameDevEditor` → `GameDev` → `GameDevCore`；GameFeatures 插件 → `GameDevCore`。

**`GameDevCore` 内容填充路线**（每填一块都有真实用途）：

| 内容 | 子目录 | 由哪个单元创建 |
|---|---|---|
| 模块骨架 | `Source/GameDevCore/`（根） | K03 |
| Native GameplayTags | `Tags/` | K15 |
| 共享枚举/结构（伤害类型、属性 ID） | `Types/` | K32 / K35 |
| 通用接口（`IInteractable`） | `Interfaces/` | K51 |
| 消息结构体（GameplayMessageSubsystem） | `Messages/` | K25 / K59 |

> 子目录**按需创建，禁止预建空目录**。
> 归属判断口诀：**"它依赖玩法实现吗？依赖 → `GameDev`；只是契约/工具 → `GameDevCore`"**。

## 3. 新增文件放哪里？——决策规则

1. **先选物理模块（DLL）**：契约/共享/工具 → `GameDevCore`；玩法实现 → `GameDev`；编辑器扩展 → `GameDevEditor`。选错模块比选错子目录严重。
2. **是 C++ 代码还是蓝图/数据？**
   - C++ → `Source/<模块>/<系统子目录>/`
   - 蓝图/DataAsset/DataTable/地图 → `Content/<对应子目录>/`
3. **C++ 归哪个逻辑层？** 对号入座：契约→`Interfaces/Tags/Types/Messages`（GameDevCore），基础设施→`Framework`，角色/属性→`Character`，技能→`Combat`，装备→`Equipment`，NPC→`NPC`，世界→`World`，界面→`UI`（均在 GameDev）。若是全新系统，在对应模块下新建英文子目录，并**同步更新本文件第 1、1.5、2 节**。
4. **一个 C++ 类 = 两个文件**：`Xxx.h`（声明）和 `Xxx.cpp`（实现），**放在同一个文件夹里，成对出现**。
5. **文件命名**：类名去掉 `U`/`A`/`F` 前缀后作为文件名，例如类 `UGameDevAssetManager` → 文件 `GameDevAssetManager.h/.cpp`。
6. **前缀规则**：`U`=UObject 子类，`A`=Actor 子类，`F`=结构体/纯 C++ 类，`I`=接口。
7. **禁止**把新文件丢在模块根目录（除模块入口 `GameDev.h/.cpp`、`GameDevCore.h/.cpp` 外）。

## 4. 一个具体例子：K01/K03 的类到底住哪

| 代码里写的 | 物理模块(DLL) | 逻辑层 | 硬盘上的真实文件 |
|---|---|---|---|
| `class FGameDevModule` | `GameDev` | 模块入口 | `Source/GameDev/GameDev.h` + `.cpp` |
| `class UGameDevAssetManager` | `GameDev` | 基础设施层 | `Source/GameDev/Framework/GameDevAssetManager.h` + `.cpp` |
| `class FGameDevCoreModule` | `GameDevCore` | 模块入口 | `Source/GameDevCore/GameDevCore.h` + `.cpp` |
| 配置 `AssetManagerClassName` | —（非代码） | — | `Config/DefaultEngine.ini` |

> 每个类都要说清"哪个 DLL、哪一层、哪个文件"三维。只写"放在 Framework/"是不够的。

## 5. 新增模块 / 目录的维护流程

- **新增物理模块**：在 `Source/<模块名>/` 创建模块目录（`<模块名>.Build.cs` + 入口 `<模块名>.h/.cpp`）→ 更新 `.uproject` 的 `Modules` 段（由用户手动，见 `_state/PLUGINS.md` 同口径）与 `.Target.cs` 的 `ExtraModuleNames` → 更新本文件第 1、1.5 节。
- **新增子目录**：在对应模块下创建目录 → 更新本文件第 1 节的树 → 更新第 2 节对照表 → 需要时在 `00-导航.md` 记录。
- 移动/删除 模块或目录：同上，保持本文件与真实工程一致。
- 每个知识单元的"生成完成后"，由智能体检查：本单元新增的文件是否已按三维登记进本文件。
